## 🚀 Development

**Install Dependencies**:

```bash
npm install
```

**Start the Development Server**:

```bash
npm run dev
```

**Build the Site**:

```bash
npm run build
```

**Check Speaking and Slide Behavior** (after building):

```bash
node --test test/*.test.js
```

The build crawls generated HTML for missing local images, responsive image
candidates, video posters, and audio/video sources before indexing search.
Run `npm run check:media` to repeat the check against an existing `dist` build.
External media hosts are not checked. Legacy `/img/` URLs used by older posts
are served from `public/img/`; keep those assets when editing or migrating posts.

## 📝 Content

Blog posts are located in `src/content/posts/`. Each post is a markdown or MDX file with frontmatter for metadata.

Site configuration is in `src/site.config.ts`.

### Speaking event sharing

Every timeline card and archive entry can share `/speaking?event={id}`. Keep event
IDs in `src/data/speaking.ts` stable when editing a talk. The link opens the same
speaking page with that card selected, not an event-detail page.

The speaking page remains **fully static**. Astro also builds selected-event
copies of the same overview under `speaking-share/`, with the correct metadata,
gallery state, and 1200 x 630 PNGs generated by
`src/pages/og/speaking/[id].png.ts`. A small Netlify edge function routes event
query links to those static copies. It does not run Astro or render HTML at
request time. The normal overview bypasses the function, and both slash forms
remain supported. Internal copies are excluded from the sitemap and marked
`noindex`; their canonical URL is `/speaking`.

Share menus support copy-link feedback, native sharing, and social destinations.
Check mouse clicks with normal animation, touch, and keyboard access as well as
reduced motion. Social platforms may require a preview re-scrape after deployment.

Run `node --test test/speaking-sharing.test.js` with Node 22.15+ for source and edge
routing tests. Set `SPEAKING_TEST_URL` to an isolated Netlify preview origin for
HTTP regression checks. Deployment verification must include a real **non-production**
Netlify preview, both speaking URL forms, and alternating/concurrent event links
before publishing to the live site. Do not replace the static page with full-page
SSR based solely on a successful local build.

Validate deployment packaging with Netlify's build command as well as Astro's
build. The router filters request methods inside the function because Netlify's
edge manifest rejects `HEAD` in an explicit method list.
